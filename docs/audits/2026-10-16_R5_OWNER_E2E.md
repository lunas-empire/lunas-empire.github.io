# Luna v53 R5 and site owner regression audit — 2026-10-16

## Root cause and change

The synthetic login response `{token, name, role, siteOwner}` matches the UI's session fields. The owner failure came from unfinished asynchronous submit handlers in `tests/native-vs-profile-links.test.js`. One test ended after observing a member-create POST, before its subsequent dashboard request and render finished. Teardown restored the global `fetch`; the late request could receive a 401, and `request()` cleared the next test's already authenticated officer. The legacy link/disable test also treated a disappearing button during loading as a completed operation.

The UI now ties 401 invalidation to the session generation that sent the request. A 401 for the current session still clears it; a delayed 401 from an older session cannot revoke a newer login. Site management UI requires either an R5 role or an R4 role with `siteOwner === true` from the login response. Tests wait for authenticated badges and for completed write renders. A controlled late-401 regression covers both old-session preservation and current-session invalidation. No client code grants server permissions.
