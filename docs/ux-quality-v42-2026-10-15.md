# Luna v42 – targeted quality upgrade, 15 October 2026
Status: Luna staging candidate; production rzsn-home and Cloudflare Worker/D1 unchanged.

## Verified fixes
1. Public VS day-selection controls now use explicit semantic foreground/background colors and avoid reduced-opacity small text. This addresses a fragile contrast cascade in dark/light appearance.
2. Public brand navigation and small section actions retain at least a 44px interaction height. Existing checklist labels remain larger clickable targets than their visible checkbox squares.
3. Daily task rows use less vertical padding while retaining at least 44px for detail actions; mobile Today statistics now use more legible secondary text.
4. OCR case search has a visible label instead of placeholder-only naming. Protected original image enlargement is a native focusable button with a visible focus state; no image opens automatically.
5. All private member/evidence trust rules preserved: unknown not zero, no unrelated top-three image fallback, manual confirmation required for any screenshot assignment.

## Quality evidence
- Original local v41 baseline: 178 passing frontend tests.
- Current candidate: 180+ automated tests; final count and release verification must be documented after the asset stamp.
- Browser Chrome CDP public routes at widths 320/390/1365 in dark/light: automated axe-core WCAG 2 A/AA, WCAG 2.1 A/AA and best practices reported zero violations for all 27 sampled combinations AFTER an adequate browser repaint following theme changes. The first quick theme-toggle run produced artificial contrast failures because computed text color updated before axe's background paint cache; explicit computed-style checks isolated the cause. Do not claim an established v41 bug without before/after repaint-controlled measurements.
- Synthetic private R5 cockpit: 10 dark/light viewport combinations (320,375,390,768,1365) produced no axe violations or document-level horizontal overflows. Not a real login or end-to-end Cloudflare operation.
- Unauthenticated GET /api/overview, /api/members, /api/reviews?status=open on staging Worker each returned HTTP 401. This checks anonymous access to these three routes only.
- Source documentation: docs/ux-deep-functional-audit.md. Screenshots, evidence JSON and automation scripts stay in private QA directory on Zentrale, outside this public repository.

## Release criteria and outstanding acceptance
Aesthetic 9.5/10 cannot be assigned solely from one person's CSS edits. Each category requires reproducible user feedback and data-integrity acceptance. Score gaps to measure:
- Visual Design: independent review of Today, VS, Season, Guides, Officer panels on phone/tablet/desktop with both themes, confirm professional consistency.
- UX: real R4 and R5 users should find OCR, train, task, player record and reports without instruction in <= 3 steps, and finish representative tasks without confusion.
- Mobile: real iPhone Safari (320–430) screenshot proof, touch/keyboard/VoiceOver, 200% text zoom and longer language strings.
- Consistency: inventory one design system and eliminate remaining game gradients and duplicate CSS implementations after visual approval.
- Data clarity: exact named-player original screenshot, metric, source hash/capture timestamp, weekly completeness and OCR uncertainty checked live.
- Functionality: actual R4/R5 write/reload/audit flows, roles and permissions, offline/timeout/error recovery.
- Release maturity: backend auth/registry, D1 snapshot backups/restore, Pages action/asset consistency, rollback scenario.

Scoring: do not assign 9.5 for any category not actually accepted. Passing automated a11y/DOM tests is necessary but insufficient for UX, security and data fidelity.
Five follow-ups: (1) real authenticated evidence/VS/donation/OCR acceptance; (2) Worker/D1 security and backup status; (3) physical iPhone Safari/VoiceOver; (4) 15-language real-layout review; (5) component-level visual consolidation guided by users.
